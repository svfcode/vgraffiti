Контракт REST для совместимых серверов (эталон — закрытый плагин vgraffiti-app). Реализация на сервере должна совпадать с этим документом.

Клиент **vgraffiti** может работать без настройки API (только локальное рисование). Ниже — контракт для **опциональной** синхронизации: сохранения, события, **мета прогулок** и `walk_id` на сервере — после входа (`Bearer`), если эндпоинт не помечен иначе.

## Базовый URL

Клиент хранит единую строку **API root**, например:

`https://example.com/wp-json/vgraffiti/v1`

Все пути ниже относительны к этому root.

## Авторизация

Для операций с данными пользователя на сервере (прогулки, сохранённые рисунки, события и т.д.) после успешного `POST /auth/verify` клиент передаёт заголовок:

`Authorization: Bearer <access_token>`

`GET /meta` и шаги `/auth/*` до выдачи токена — без Bearer, если не оговорено отдельно.

---

### `GET /meta`

Проверка живости и версии (без авторизации).

**Ответ 200:** `application/json`

```json
{
  "ok": true,
  "version": "0.0.1",
  "api": "vgraffiti/v1"
}
```

Поля могут расширяться; клиенту достаточно `ok === true`. Клиент **vgraffiti** в popup после «Проверить адрес» выводит краткое текстовое резюме (версия, префикс API, доп. поля списком), без обязательного показа сырого JSON.

---

### `POST /auth/email`

**Тело:** `{ "email": "user@host" }`

**Ответ:** `204` без тела или `200` с нейтральным JSON (например `{ "sent": true }`).

Не раскрывать факт существования аккаунта.

---

### `POST /auth/verify`

**Тело:** `{ "email": "user@host", "code": "123456" }`

**Ответ 200:**

```json
{
  "access_token": "...",
  "expires_at": "2026-01-01T12:00:00.000Z",
  "user": { "email": "user@host" }
}
```

`expires_at` может быть `null`, если сервер выдаёт бессрочный токен до отзыва.

---

### `POST /auth/logout`

С заголовком Bearer — инвалидация текущего токена. **Ответ:** `204` или `200`.

---

### Прочее (черновик ТЗ плагина)

Эндпоинты ниже предполагают **Bearer** (кроме явных исключений в реализации сервера):

- `POST /walks`, `PATCH /walks/{id}` — **мета прогулок** на сервере
- `POST /drawings` (+ файл)
- `POST /events`
- `GET /drawings`, `GET /drawings/{id}`

Заголовок `Idempotency-Key` на идемпотентных `POST` — рекомендуется.

Коды ошибок: тело JSON при возможности `{ "code": "...", "message": "..." }`.
