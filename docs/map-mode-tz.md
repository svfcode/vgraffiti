# ТЗ: режим карт (vgraffiti)

Документ задаёт целевое поведение расширения **vgraffiti** на страницах интерактивных карт (Google Maps, Яндекс.Карты). Это **отдельная спецификация** для карты; общие требования к расширению — в [tz.md](./tz.md), контракт API — в [api.md](./api.md).

---

## 1. Назначение

Пользователь рисует поверх карты в браузере и сохраняет рисунок на сервер. При перемещении по карте или изменении масштаба рисунок адаптируется и отображается в области окна просмотра в виде, соответствующем проекции карты.

Ключевая идея: рисунок — это слой, привязанный к **координатам и масштабу карты**, а не к пикселям окна браузера.

---

## 2. Область действия

| Поддерживается | Не входит в v1 |
|----------------|----------------|
| Google Maps (`/maps/…`) | Street View / панорамы |
| Яндекс.Карты (`yandex.*/maps/…`, `maps.yandex.ru`) | Офлайн-карты, PDF |
| Десктоп Chromium (Chrome, Edge) | Мобильные браузеры без расширений |

---

## 3. Термины

| Термин | Описание |
|--------|----------|
| **Контекст карты** | Центр видимой области: `lat`, `lng`, `zoom`, `map_provider` (`yandex` \| `google`). |
| **Ячейка карты (`map_cell`)** | Ключ upsert: `provider:lat:lng` с округлением до 5 знаков (~1 м). Одна ячейка — один рисунок пользователя. |
| **Viewport** | Видимая область браузера (окно), в которую сохранён PNG слоя. |
| **Режим «Нав»** | Карта управляется как обычно; overlay не перехватывает указатель. |
| **Режим «Рис»** | Рисование на canvas overlay; карта под слоем не двигается. |
| **Слой** | Загруженный с сервера PNG + метаданные (`lat`, `lng`, `zoom`). |
| **Локальные штрихи** | Ещё не сохранённые мазки поверх активного слоя. |

---

## 4. Роли UI на карте

### 4.1. Переключатель «Нав» / «Рис»

- **«Нав»** — `pointer-events: none` на canvas; pan/zoom карты работает штатно.
- **«Рис»** — canvas перехватывает указатель; рисование, ластик, фигуры.

### 4.2. Когда какой режим включать

| Ситuation | Режим по умолчанию |
|-----------|-------------------|
| Открыли карту по ссылке «Открыть» из профиля, рисунок загружен, новых штрихов нет | **«Нав»** |
| Пользователь нажал «Рис» или начал новый штрих | **«Рис»** |
| После «Очистить» / удаления всех локальных штрихов при просмотре | снова **«Нав»** (опционально, если нет несохранённых правок) |

---

## 5. Режим сохранения

Под «сохранением» понимается передача слоя на сервер и запись привязки к карте.

### 5.1. Условия сохранения

- Активная сессия (`Bearer` в storage).
- Настроен и доступен базовый URL API.
- Определён **контекст карты** (см. §5.2). Без координат — ошибка «координаты карты не определены», сохранение не выполняется.

### 5.2. Что фиксируется при сохранении

В запрос `POST /drawings` уходят:

| Поле | Источник | Назначение |
|------|----------|------------|
| `lat`, `lng` | Центр карты в момент сохранения | Якорь рисунка на местности |
| `zoom` | Масштаб карты | Масштаб слоя относительно viewport |
| `map_provider` | `yandex` или `google` | Формирование `map_cell` |
| `meta.map` | Дублирование координат в JSON | Совместимость со старыми записями |
| PNG | Canvas: активный слой + локальные штрихи | Растровый артефакт |
| `pageUrl` (в meta) | `location.href` | Отладка, ссылка на контекст |

PNG соответствует **полному viewport** в момент сохранения: рисунок «накрывает» видимую область окна.

### 5.3. Upsert по ячейке

- Сервер вычисляет `map_cell` из `map_provider` + округлённых `lat`/`lng`.
- Если у пользователя уже есть рисунок в этой ячейке → **обновление** (тот же `id`, новый файл, `updated_at`).
- Иначе → **создание** новой записи (`201`).

Повторное сохранение в той же точке не создаёт дубликаты в галерее.

### 5.4. Поведение после успешного сохранения

- Локальные штрихи сливаются в загруженный слой (flatten).
- Ответ API: `updated: true | false` — показать «Сохранено на карте» / «Рисунок на карте обновлён».
- Аккаунт расширения и WordPress должны совпадать по **email**, иначе рисунок не виден в профиле пользователя.

### 5.5. Ошибки сохранения

| Ситуация | Поведение |
|----------|-----------|
| Нет сессии | Подсказка: войти через popup расширения |
| Нет координат | Ясное сообщение, без silent fail |
| HTTP 4xx/5xx | Текст ошибки; вложение на сервере не остаётся «висящим» без записи в БД |
| Mixed content (HTTPS карта → HTTP API) | Загрузка через service worker |

## 6. Режим отрисовки

Под «отрисовкой» понимается показ сохранённых (и при редактировании — текущих) слоёв поверх карты.

### 6.1. Загрузка слоёв

- При открытии карты с активной сессией: **один раз** (и при появлении координат в URL) — `GET /drawings?near=1` с `lat`, `lng`, `radius`, `map_provider`.
- **Движение карты**: положение слоёв пересчитывается **локально**, без запроса на каждый кадр (§6.2, §6.4).
- После **паузы ~2,8 с** после последнего изменения центра выполняется **фоновый** `GET /drawings?near=1`: ответ **сливается по `id`** (`merge`), уже загруженные PNG **не удаляются** даже если ответ временно пуст или отличается от центра.
- Радиус — примерно половина видимой области (с запасом).
- Изображения подгружаются по `file_url` (через SW при необходимости CORS).
- Загруженные слои хранятся в **памяти вкладки**, пока её не очистят; явный полный reload — сохранение, вход, первый захват координат карты.

### 6.2. Геопривязка (обязательное поведение)

Рисунок, сохранённый с центром `(lat₀, lng₀)` и zoom `z₀`, при текущем центре `(lat₁, lng₁)` и zoom `z₁` размещается так:

1. Вычислить смещение точки `(lat₀, lng₀)` относительно `(lat₁, lng₁)` в пикселях Web Mercator при zoom `z₁`.
2. Масштаб слоя: `2 ** (z₁ - z₀)` относительно размеров viewport.
3. Прямоугольник на экране: центр viewport + смещение − половина ширины/высоты масштабированного слоя.

**Ожидаемый эффект для пользователя:** обвёл город — при pan карты обводка **остаётся на городе** и **смещается по окну браузера** (уезжает в сторону, если смотреть другой район).

### 6.3. Когда слой на весь экран (исключение)

Полноэкранная отрисовка (`0, 0, viewportW, viewportH`) **только** если одновременно:

- режим **«Рис»**, и
- редактируется **активная ячейка**, и
- есть **локальные шtрихи** или идёт жест рисования.

Во всех остальных случаях (просмотр, «Нав», «Рис» без новых штрихов) — **только геопривязка**.

### 6.4. Отслеживание движения карты

Для пересчёта позиции слоя при pan/zoom клиент должен получать актуальный центр карты:

| Источник | Когда |
|----------|--------|
| URL (`ll=`, `@lat,lng,z`) | Старт, смена URL, конец pan |
| ymaps API (`boundschange`, `getCenter`) | Яндекс, если API доступен в page context |
| Смещение указателя при pan | Fallback: накопление `movementX/Y` пока пользователь тянет карту в режиме «Нав» / просмотра |

Правила:

- Во время перетаскивания карты overlay **перерисовывается**, рисунок **не исчезает**.
- **`GET /drawings` во время удержания/анимации карты не выполняется** — только после остановки (debounce), фоновый merge.
- После **`POST /drawings`** (успешное сохранение) список можно обновить с сервера снова.
- CPU: без бесконечных циклов `requestAnimationFrame` в page script; без запросов к API на каждый кадр или на каждый жест карты.

### 6.5. Несколько рисунков

- В viewport могут быть слои из разных ячеек (соседние сохранения).
- Каждый позиционируется по **своим** `lat`, `lng`, `zoom`.
- Активная ячейка (совпадает с текущим `map_cell` центра) — кандидат на редактирование; остальные — только просмотр.

### 6.6. Zoom

- При изменении zoom масштаб слоя меняется по формуле §6.2.
- Центр масштабирования — geographic anchor рисунка, не центр экрана.

## 7. Связь с сервером (кратко)

Реализация — плагин **vgraffiti-app** (см. [`docs/tz.md`](../../wp-content/plugins/vgraffiti-app/docs/tz.md), серверное ТЗ карт — [`docs/map-mode-tz.md`](../../wp-content/plugins/vgraffiti-app/docs/map-mode-tz.md)).

| Требование | Деталь |
|------------|--------|
| Таблица `vgf_drawings` | Колонки `lat`, `lng`, `zoom`, `map_provider`, `map_cell` |
| UNIQUE `(user_id, map_cell)` | Upsert |
| Профиль BuddyPress | Вкладка «Мои рисунки»; кнопка «Открыть» → карта с `ll=` / `@` в **новой вкладке** |
| REST list nearby | `GET /drawings?near=1&lat=&lng=&radius=` |

## 8. Критерии приёмки

### Сохранение

- [ ] Сохранение в точке A создаёт запись с координатами A.
- [ ] Повторное сохранение в той же ячейке обновляет запись, не дублирует.
- [ ] Рисунок виден в профиле того же пользователя (email совпадает).

### Отрисовка

- [ ] Открыли карту по ссылке из профиля — рисунок виден.
- [ ] Режим «Нав»: pan карты — рисунок **смещается по окну** и остаётся на месте на карте (не «едет за пальцем» как HUD).
- [ ] Рисунок **не пропадает** в процессе pan.
- [ ] Zoom in/out — размер слоя меняется согласованно с картой.
- [ ] Режим «Рис» + новый штрих — удобное редактирование на весь экран; после сохранения снова геопривязка при просмотре.

### Производительность

- [ ] Нет 100% CPU от overlay при простом просмотре карты.
- [ ] Нет лавины HTTP-запросов при удержании pan.

## 9. Порядок реализации (рекомендуемый)

1. **Контекст карты** — стабильное чтение `lat`/`lng`/`zoom` (URL + page bridge).
2. **Отрисовка** — геопривязка по §6.2–6.4; только потом полировка UX.
3. **Сохранение** — upsert, flatten, сообщения пользователю.
4. **Профиль** — галерея и ссылки на карту.
5. Регрессии: кэш слоёв, фоновый merge nearby, режимы «Нав»/«Рис».
