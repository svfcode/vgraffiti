# ТЗ: расширение браузера vgraffiti

## 1. Назначение и модель распространения

Расширение **open source**, публикуется в открытом доступе. Работает поверх веб-карт с уличной панорамой (в первую очередь Google Street View в браузере), даёт слой для рисования **сразу после установки**, без обязательного сервера и без входа. Отправка на бек **метаданных**, **артефактов рисунка** (растровый слой, превью), **меты прогулок** и синхронизация включаются **только после** опциональной настройки API и авторизации по почте. Без опоры на платный Street View Static API на каждый шаг навигации.

**Привязки к конкретному хосту в коде расширения нет:** взаимодействие только по **REST** с настраиваемым базовым URL. Фактический сервис автора строится на **закрытом** (не open source) плагине WordPress `vgraffiti-app` — см. внутреннее ТЗ `wp-content/plugins/vgraffiti-app/docs/tz.md`; исходники плагина **не** публикуются. Сторонний сервер возможен только если кто-то самостоятельно реализует **совместимый** REST по спецификации, опубликованной вместе с расширением.

## 2. Целевые платформы

- Chromium: Chrome, Edge, браузеры на базе Chromium (Manifest V3).
- Минимальная версия API расширения — согласно выбранному `minimum_chrome_version` в манифесте (зафиксировать при первой сборке).

Firefox/Safari — вне скоупа первой версии, если не оговорено отдельно.

## 3. Состав и архитектура

| Компонент | Роль |
|-----------|------|
| **Service worker (background)** | Жизненный цикл, запросы к REST выбранного сервера, очередь при офлайне, обновление сессии, алармы для отложенной отправки. |
| **Content script(s)** | Определение страницы панорамы, оверлей рисования, сбор метаданных кадра, снимок слоя. |
| **Popup / options** | Краткая справка: рисование без входа; **опционально** — базовый URL API, вход по почте (код из письма), статус сессии и выход для синхронизации и меты прогулок. |
| **Локальное хранилище** | `chrome.storage`: базовый URL API, токен сессии (или аналог), черновики, очередь событий, настройки кисти. |

**Пароли в продукте не используются.** Если пользователь включает синхронизацию, вход — одноразовый код из письма на указанный email; владение почтой одновременно и фактор входа, и по сути замена отдельной 2FA на этом шаге.

### 3.1. Локальное использование и опциональная связка с сервером

**Без первичной настройки:** на разрешённых URL карты активируется оверлей рисования; пользователь может рисовать **без** указания API и **без** входа. Содержимое слоя в этой модели **только на клиенте** (в пределах жизни вкладки / сессии оверлея), на сервер ничего не уходит.

**По желанию — синхронизация и мета прогулок:** когда пользователю нужны сохранение на бек, учёт прогулок и связанная **мета**, он в popup задаёт сервер и проходит вход по почте и коду. Далее:

1. Пользователь вводит **базовый URL** REST (например `https://example.com/.../vgraffiti/v1` — по контракту).
2. Расширение при запросе пользователя проверяет доступность API (например `GET /meta`).
3. Пользователь вводит **email** → запрос кода → **письмо с кодом**.
4. Ввод **кода** → обмен на **сессионный токен**, сохранение в `chrome.storage`.
5. Включаются операции с беком: сохранения, **прогулки** (`walk_id` и мета на сервере), события — с `Authorization` по контракту.

Ограничения: cooldown повторной отправки кода, отображение ошибок сети и ответов API пользователю. Функции, требующие идентификации пользователя или серверного `walk_id`, при отсутствии сессии **не выдают** данные с сервера и по возможности объясняют в UI, что нужен вход.

### 3.2. Разрешения манифеста и произвольный хост

У каждого инстанса свой origin. **Запрос host permission** к API — только когда пользователь сохраняет URL и/или вызывает проверку `/meta` или вход (не требуется для локального рисования). Домены карт (Street View и т.д.) — отдельно по согласованному списку шаблонов. В README: сценарий «рисование сразу» и отдельно «опционально: URL API → разрешение домена → вход».

## 4. Функциональные требования

### 4.1. Рисование

- Оверлей (canvas или аналог) поверх области панорамы, синхронизация размеров при ресайзе окна и смене ориентации панорамы.
- Инструменты: **кисть** (размер по ползунку), **ластик** (отдельный размер), **стрелка** и **квадрат** (толщина/масштаб линии от размера кисти); выбор цвета — **палитра квадратиков** (пресеты). **Очистить** — в меню «⋯».
- Переключатель **Нав** / **Рис**: в режиме навигации canvas не перехватывает указатель (карта крутится как обычно); в режиме рисования — рисование и инструменты.
- **Отмена / повтор:** стек истории штрихов; кнопки **↶** / **↷** и сочетания **Ctrl+Z** / **Ctrl+Shift+Z** (на macOS — **Cmd** вместо Ctrl). **Ctrl+Y** / **Cmd+Y** — быстрое сохранение на сервер (как дискета, без открытия формы входа гостем). В полях ввода страницы шорткаты не перехватываются.
- Ввод: **Pointer Events** (`pointerdown` / `move` / `up`, при необходимости `cancel`). Для графического планшета и пера учитывать `pointerType === 'pen'`, **`pressure`** (0…1), при необходимости наклон — `tiltX` / `tiltY` (если браузер и устройство отдают).
- **Плотность точек и планшет:** в `pointermove` обрабатывать **`getCoalescedEvents()`** — промежуточные отсчёты пера между кадрами отрисовки не теряются, линия не «рвётся». Где доступно, для минимальной задержки рассмотреть **`pointerrawupdate`** (с тем же учётом coalesced, если применимо к цепочке событий в целевом браузере).
- **Давление в логике штриха:** не подменять реальное давление мышью без явного режима; для мыши — отдельная ветка (например постоянная толщина или симуляция по скорости — по политике продукта).
- **Рендер:** отрисовка штриха в **`requestAnimationFrame`** (буфер точек за кадр), без тяжёлой работы в каждом сыром событии сверх разумного.
- **Библиотека (рекомендуемый дефолт):** [perfect-freehand](https://github.com/steveruizok/perfect-freehand) — на вход массив точек с `pressure`, рендер контура на canvas/SVG; для пера **`simulatePressure: false`**. Допустима замена на собственный canvas-код при сохранении тех же требований к pressure и coalesced.
- Режим «черновик» локально до явного «Сохранить на сервер» или автосейв по таймеру (настраиваемо).

### 4.2. Метаданные кадра (пример состава, уточняется контрактом API)

Передавать только то, что нужно для галереи и аналитики; без лишних PII.

- Время (UTC), часовой пояс клиента (опционально).
- Идентификатор сессии рисования / прогулки.
- URL страницы (или нормализованный шаблон без query — по политике приватности).
- Координаты, heading/pitch/zoom — **только если доступны легально из DOM/стейта страницы**; недоступное не выдумывать.
- Версия расширения.

### 4.3. Отправка на сервер

- Имеет смысл **только при** сохранённом API и активной сессии (Bearer). Без входа отправка рисунков, событий и серверных прогулок не выполняется (локальный режим).
- Только **REST** на сохранённый базовый URL; версия API в пути (`/v1/` и т.д.) — по документированному контракту.
- Форматы: JSON для мета + `multipart/form-data` для файла слоя (PNG/WebP) или двухфазная загрузка — как договорено в контракте.
- Повтор при 5xx / сетевой ошибке с backoff; заголовок **Idempotency-Key** для идемпотентных `POST`.
- При **401** — попытка обновления сессии по контракту или предложение войти заново (новый код на почту).
- Лимиты размера и частоты — из ответов API, показывать пользователю понятные сообщения.

### 4.4. «Прогулка»

- **Серверная прогулка** (мета и `walk_id` на беке): только после входа — серия точек / сохранений с общим `walk_id`, выданным сервером при `POST /walks`; завершение — отдельные вызовы API.
- **Локальный режим:** прогулка как сущность на сервере **не ведётся**; при появлении UX «локальной прогулки» она не смешивается с серверной метой без явного переключения режима (уточнить при реализации).

### 4.5. Безопасность и приватность

- Минимальные permissions; доступ к API-хосту — по явному выбору пользователя.
- В onboarding кратко: рисование можно без сервера; при включении синхронизации — какой сервер и что уходит на него (рисунки, мета, события, мета прогулок).
- Полные скриншоты панорамы не отправлять без явного согласия пользователя, если это не часть продукта.

## 5. Нефункциональные требования

- Производительность: отрисовка без заметных лагов; планшетный ввод — за счёт coalesced + rAF (см. §4.1); throttle для автосейва.
- Локализация UI: русский в v1, архитектурно готовность к i18n.
- Сборка: артефакт для Chrome Web Store + инструкция unpacked; лицензия open source в репозитории.

## 6. Критерии приёмки (черновик)

- **Без** настройки API и **без** входа пользователь открывает карту и может рисовать в оверлее (локально).
- При желании: указать совместимый сервер, пройти вход по email+коду и получить успешный ответ API (например `/meta`, далее синхронизация по мере реализации).
- Расширение активно только на согласованных URL карты; на остальных сайтах не мешает.
- Очередь при офлайне и восстановлении связи без дублей (idempotency).
- Ошибки API не глотаются.
- С пером/графическим планшетом толщина или плотность штриха зависит от **реального** `pressure` (без деградации до «как мышь»), линия при быстром движении пера остаётся сплошной за счёт coalesced-событий.

## 7. Контракт API

- Эндпоинты, поля JSON, коды ошибок, формат авторизации (заголовок с токеном) — описываются **в открытом репозитории расширения** (`docs/api.md`, OpenAPI и т.д.), чтобы любой мог написать совместимый сервер или проверить клиент. Код сервера при этом остаётся закрытым.
- Расширение не содержит хардкода чужих продакшен-URL.

## 8. Вне скоупа (по умолчанию)

- Публикация в Chrome Web Store (юридические тексты, скриншоты) — отдельная задача.
- Серверный рендер панорам через Google Street View API.
- Мобильные приложения.
